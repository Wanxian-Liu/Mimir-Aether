LogRecord Factory Injection（会话上下文注入）\n\n```python\n# 不使用 Filter，直接在 LogRecord 创建时注入 session_tag\n# 优势：所有 handler/formatter 都能安全使用 %(session_tag)s，无 KeyError\n_install_session_record_factory()  # 模块导入时立即安装\n\ndef set_session_context(session_id: str):\n    _session_context.session_id = session_id  # thread-local\n```\n\n**设计理由**：Filter 只能在特定 handler 生效，如果第三方 handler 使用含 `%(session_tag)s` 的格式会崩溃。Record Factory 是进程中唯一的记录创建点，注入后全局可用。\n\n#### 2. RedactingFormatter（密钥脱敏）\n\n```python\n# 所有 handler 统一使用 RedactingFormatter\n# 保证 API Key/Token 不会写入任何日志文件\nformatter=RedactingFormatter(_LOG_FORMAT)\n```\n\n**设计理由**：中心化脱敏优于分散检查。无论日志从哪个 logger 发出、路由到哪个 handler，都会被同一脱敏逻辑处理。\n\n#### 3. Component-Based Log Routing\n\n```python\n# gateway.log 只接收 gateway.* 前缀的记录\n# agent.log 是 catch-all（接收所有）\nCOMPONENT_PREFIXES = {\n    \"gateway\": (\"gateway\",),\n    \"agent\": (\"agent\", \"run_agent\", \"model_tools\", \"batch_runner\"),\n    \"tools\": (\"tools\",),\n}\n_ComponentFilter(prefixes)  # 简单高效的 prefix 匹配\n```\n\n**设计理由**：多模式部署（CLI + Gateway 常驻进程）需要组件隔离，但 agent.log 保留完整记录用于事后调试。\n\n#### 4. DebugSession No-Op Pattern（零成本调试开关）\n\n```python\nclass DebugSession:\n    def __init__(self, tool_name, *, env_var):\n        self.enabled = os.getenv(env_var, \"false\").lower() == \"true\"\n        # 禁用时所有方法都是廉价 no-op\n\n    def log_call(self, call_name, call_data):\n        if not self.enabled: return  # 零开销\n        ...\n```\n\n**设计理由**：生产环境零性能损耗，调试时只需设置环境变量而无需改代码。\n\n#### 5. Paste-Upload Debug Sharing\n\n```python\n# hermes debug share → 自动收集 dump + log tails + full logs → 上传到 paste.rs\n# 一键获得可分享的 URL，降低支持成本\n```\n\n**设计理由**：用户无需手动找日志文件、复制粘贴 — 一条命令完成所有诊断信息收集。\n\n---\n\n## 体系存在\"不同 handler 有不同 filter\"的问题。如果一个 handler 的 formatter 引用了 `%(session_tag)s` 但没有对应的 Filter 注入该字段，就会触发 KeyError。Record Factory 在 LogRecord 创建时统一注入，解决全局一致性问题。\n\n### 亮点 2: RedactingFormatter — 防线前置\n**设计理由**：与其在每个日志调用点手动脱敏（容易遗漏），不如在输出端统一拦截。即使新代码忘记脱敏，数据也不会泄露到磁盘。\n\n### 亮点 3: 组件级日志路由\n**设计理由**：Gateway 常驻进程和 CLI 单次执行产生不同关注点的日志。通过 `_ComponentFilter` 实现零配置路由，agent.log 保持完整可用于事后关联分析。\n\n### 亮点 4:
