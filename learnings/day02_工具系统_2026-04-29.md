### 1.2 Hermes model_tools.py 关键设计

#### A. 异步桥接（Async Bridging）
```python
# 全局持久化事件循环 (主线程)
_tool_loop = None
_tool_loop_lock = threading.Lock()

# 每线程独立持久化循环 (工作线程)
_worker_thread_local = threading.local()

def _get_tool_loop():
    """返回主线程的长生命周期事件循环"""
    global _tool_loop
    with _tool_loop_lock:
        if _tool_loop is None or _tool_loop.is_closed():
            _tool_loop = asyncio.new_event_loop()
        return _tool_loop

def _get_worker_loop():
    """返回当前工作线程的持久化循环"""
    loop = getattr(_worker_thread_local, 'loop', None)
    if loop is None or loop.is_closed():
        loop = asyncio.new_event_loop()
        asyncio.set_event_loop(loop)
        _worker_thread_local.loop = loop
    return loop
```

**防止**: "Event loop is closed" 错误（asyncio.run()每次创建+关闭循环）

## 四、关键发现

### 发现1: MimirAether有双工具注册表
**现象**: MimirAether同时使用:
1. `tools/registry.py` - Hermes注册表（来自tools/*.py自注册）
2. `agent/tool_registry.py` - 自研SQLite注册表

**问题**: 这两套系统没有互通！agent/tool_registry.py的工具有注册但不会被Hermes的registry识别。

### 发现2: model_tools.py严重简化
**现象**: Hermes有600行的model_tools.py，MimirAether只有104行。

**根因**: MimirAether可能依赖OpenClaw原生工具系统，而非Hermes的手动工具分发。

### 发现3: 工具发现机制在MimirAether缺失
**现象**: Hermes的`_discover_tools()`显式导入22个工具模块，MimirAether没有类似机制。

**问题**: MimirAether的Hermes兼容工具（tools/*.py）可能根本没有被导入注册。
