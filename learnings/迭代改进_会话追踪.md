## 三、技术选型

| 选项 | 决策 | 理由 |
|------|------|------|
| SQLite vs PostgreSQL | **SQLite** | 轻量、无依赖、单文件、适合本地存储 |
| 同步 vs 异步 | **同步** | 简单场景无需异步开销 |
| 胖表 vs 瘦表 | **分表** | 事件与主表分离，减少主表膨胀 |
| JSON vs 独立字段 | **JSON** | 元数据和事件数据灵活扩展 |

## 七、经验总结

### SQLite 最佳实践
1. 使用 `row_factory` 获取字典式行对象
2. 用 `rowcount` 检查 UPDATE/DELETE 影响行数
3. JSON 字段用 `json.dumps/loads` 序列化
4. 时间戳统一用 ISO 8601 格式

### 模块设计原则
1. **默认路径自创建** - 无需手动创建目录
2. **失败返回 False** - 不抛异常，便于调用方处理
3. **可选参数有默认值** - 降低使用门槛
