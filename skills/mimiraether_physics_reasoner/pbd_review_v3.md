## 3. 代码逐行审计

### 3.1 碰撞解析 (L141-167)

```python
# 位置修正 (质量加权)
wi = inv_mass[i] / (inv_mass[i] + inv_mass[j])
s[oi:oi+3] += wi * penetration * n
s[oj:oj+3] -= wj * penetration * n
```

**✅ 正确。** PBD 标准公式。质量大的物体移动少，质量小的移动多。静态体 (mass→∞, inv_mass→0) 不动。

```python
# 速度修正
vn = np.dot(v_rel, n)
if vn < 0:  # 接近中
    j_imp = -(1 + e) * vn / (inv_mass[i] + inv_mass[j])
```

**✅ 正确。** Sequential Impulse 标准公式。`if vn < 0` 只在接近时修正——避免分离时错误加速。

### 3.2 关节解析 (L170-187)

```python
C = dist - jt['rest_length']  # 约束违反量
correction = k * C
s[oi:oi+3] -= wi * correction * n
```

**✅ 正确。** PBD 距离约束。`k * C` 而非 PBD 标准公式 `C / (wi + wj)` 的原因：`k` 是用户可调的柔度参数，允许关节有弹性。对刚体关节设 `k=1.0` 即可。

### 3.3 接地约束 (L66-77)

```python
if s[o + 1] < y:
    s[o + 1] = y
    if s[o + 4] < 0:
        s[o + 4] = -s[o + 4] * restitution
```

**✅ 正确。** 地面在 `_solve_pbd` 之前执行（作为 `constraints` 回调），防止 PBD 把物体推出地面。

## 5. 设计合理性评估

### 5.1 架构分层 ✅

```
力计算 (_compute_acceleration)
    ↓
积分步 (RK4/Verlet/Leapfrog4/Euler)
    ↓
硬约束 (constraints: 接地)
    ↓
PBD迭代 (_solve_pbd: 碰撞 + 关节)
```

**评价**: 力/积分/约束三层分离，清晰。PBD 放在积分步之后是标准做法——先让物理推动物体，再修正非法状态。

### 5.2 PBD vs 约束回调 职责划分 ✅

| 约束类型 | 实现方式 | 理由 |
|----------|---------|------|
| 地面 (单向不等式) | `add_ground` → constraints 回调 | 简单，不参与质量加权 |
| 碰撞 (两体不等式) | `add_collision_pair` → PBD | 质量加权必需 |
| 关节 (两体等式) | `add_joint` → PBD | 质量加权必需 |
| 弹簧力 (单体力) | `add_spring` → forces | 力而非约束 |

### 5.3 理论正确性 ✅

- **Sequential Impulse**: 冲量公式与 Box2D/Bullet 一致
- **PBD 距离约束**: 与 Müller 2007 原始论文一致
- **质量加权**: 正确区分静态体 (inv_mass→0) 和动态体

## 6. 发现的问题

### 6.1 🟡 关节无速度级修正

**现状**: 关节只做位置修正 (L181-186)，不做速度修正。  
**影响**: 关节连接的物体会在约束位置附近微幅振荡（非发散，有界）。  
**根因**: PBD 距离约束不天然保速度——这是方法本身的特性，不是 Bug。  
**判断**: **设计取舍合理。** 对物理教学/推理场景，位置级精度已足够。速度级保约束需要 Lagrange Multiplier 或 Featherstone 算法，复杂度 ×10。  
**建议**: 如未来需要更高精度（路线 3 规划引擎），可升级为 `SequentialImpulse+WarmStart` 或 `Featherstone`。当前不修。

### 6.2 🟡 无 Warm Start

**现状**: 每次 `_solve_pbd` 从零开始迭代，不重用上一步的累积冲量。  
**影响**: 需要更多迭代次数才能收敛。当前 5 次迭代对 3 体场景足够（已验证），但对 10+ 体可能不够。  
**判断**: **当前受控。** N≤3 时 5 次迭代收敛良好。这是后续颗粒（多体扩展）的职责。  
**建议**: 当 N 扩展到 10+ 时，加入 `accumulated_impulse` 缓存 + warm start。

### 6.3 🟡 双摆基线失败未被 PBD 修复

**现状**: `test_baseline_v2.py` 场景 4 (双摆) D3 保结构 `max_dL1=4.6515m → FAIL`。  
**根因**: 基线测试用 `add_constraint(绳约束回调)` 而非 `add_joint(PBD)` 来实现双摆——这是两套不同的约束系统。  
**判断**: **测试设计问题，非 PBD 缺陷。** 基线 v2 写于颗粒 2 之前，使用旧的约束回调机制。PBD 关节 (T4b) 已证明能正确保持摆长。  
**建议**: 为双摆写一个用 `add_joint` + PBD 的专项测试，验证 PBD 关节是否也能解决双摆保结构问题。

### 6.4 🟢 碰撞对使用全局索引

**现状**: `add_collision_pair(0, 1, ...)` 直接使用 `self.bodies` 的全局索引。  
**判断**: **设计合理。** 这是 Bullet/Box2D 的标准做法——碰撞对在添加时就绑定到具体的 body 索引。删除/重排 body 会导致索引失效，但当前引擎不支持 body 的动态增删，所以不是问题。  
**建议**: 如未来支持动态场景（路线 3），改 UUID 绑定。
