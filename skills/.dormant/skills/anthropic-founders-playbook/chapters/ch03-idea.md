# Chapter 3 — Idea Stage

## 目标
研究型验证：在投入资源建造前，组装"真实问题存在且你的方案有效"的扎实证据。

## 必答问题（按顺序）
1. 这个问题真实、具体、频繁到值得围绕它建造吗？
2. 谁确切有这个问题，那是市场吗？
3. 有人解决它吗？怎么解决、解决得如何？
4. 解决方案实际需要做什么？我的想法能做到吗？

汇总为终极问题：**这值得建造吗？**

## 退出标准（问题-解决方案契合，三问全yes）
1. 问题真实且具体？——能说出谁遇到它、多频繁、多严重、他们现在怎么做
2. 方案解决的是实际问题（验证揭示的那个，不一定是原来假设的那个）？
3. 信号够了吗？——足够的定性证据让"投入MVP"是理性决策而非信念之跃

## 反模式
- **把建造当验证**：42%的创业失败是因为造了没人要的东西。原型≠证据，它是和潜在用户对话的压力测试工具。对话本身才是真证据
- **过早扩张**：建造毫不费力时，容易在执行上远超业务需求。首要指令：**让sense-making跑在building前面**
- **丧失客观性**：确认偏误现在有研究引擎加持。AI会为你的信念找支持证据。解药是同一工具反方向用：让它压力测试你的想法
