## 技能要点

# 技能集成标准流程

新技能从"孤岛"变成"基础设施"，通过修改调用方 SKILL.md 实现。

## 三步法

### Step 1: 识别集成点
在调用方技能中找"决策节点"——流程中的自然停顿点，新能力可以插进去增强而不打断流程。

| 调用方类型 | 典型集成点 |
|------------|-----------|
| 流程类技能（brainstorming） | 阶段/Stage 之间 |
| 基建类技能（context-engine） | 加载时、判断条件后 |
| 触发类技能（tool-triggers） | 必用场景列表 |

### Step 2: 设计集成行为
定义三个要素：
- **触发条件**：什么时候调用新技能（精确到关键词/条件判断）
- **可见性**：结果对用户可见（建议/确认）还是静默（注入/跳过）
- **fallback**：新技能不可用或无命中时的退路

### Step 3: 最小改动实现
- 只在调用方 SKILL.md 中新增一个章节（≤40行）
- 不改新技能本身
- 不改调用方的其他章节
- 不改任何 Python 代码

## 验证清单

- [ ] 新增章节位置正确（在目标章节之后/之前）
- [ ] 原有章节未被覆盖/破坏
- [ ] 三份副本同步（仓库 + ~/.mimiraether/skills/ + ~/.openclaw/skills/）
- [ ] commit + push

## 反模式

- 改新技能本身来"适配"调用方
- 一口气集成多个调用方（一次一个，commit 隔离）
- 集成时顺手重构调用方其他部分
- 跳过验证直接 commit
