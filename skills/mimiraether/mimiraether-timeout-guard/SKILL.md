# MimirAether Timeout Guard — 超时防护系统

基于超时根因分析构建的四层防护：任务分级 → 时间预算 → 沉没开关 → 熔断机制。

## 1. 任务深度分级

开始任何任务前，先判定层级：

| 层级 | 定义 | 典型任务 | 时间预算 |
|------|------|----------|----------|
| **L1·瞬答** | 单工具、已知答案、无推理链 | 读文件、查环境变量、简单搜索 | ≤15s |
| **L2·浅析** | 2-5工具、简短推理、单一依赖链 | 查文档+执行、代码片段修改、数据查询 | ≤60s |
| **L3·深潜** | 多工具、长推理链、多依赖交错 | 根因分析、架构重构、跨模块实现 | ≤900s |

**判定规则**：不确定时取高一级（宁可多预算不超时）。

## 2. 时间预算与检查点

### 预算分配
- 总预算 = 层级上限 × 0.8（留20%缓冲做熔断）
- L3总预算：900s × 0.8 = 720s 有效执行时间
- 每消耗5个工具调用或60s，做一次检查点判定（L3放宽）：
  - ✅ 在预算内且进展正常 → 继续
  - ⚠️ 接近预算边缘（>70%）→ 精简后续步骤，关闭沉没模式
  - 🔴 超预算 → 触发熔断

### 工具调用计数
- 每轮工具调用后自检：`已用调用数 / 预算剩余时间`
- L3任务每8次调用强制输出一次中间状态（防止静默超时）

## 3. 沉没开关（Sinking Switch）

控制 `thinking_mode` 的开闭，避免过度沉思导致超时。

| 层级 | 沉没模式 | 策略 |
|------|----------|------|
| L1 | ❌ 关闭 | 直接行动，不进入思考模式 |
| L2 | ⚡ 轻度 | 仅首轮开启，后续关闭 |
| L3 | ✅ 开启 | 全程开启，但每5轮工具调用后关闭一轮以同步状态 |

**动态切换规则**：
- 检测到连续3轮无工具调用的纯思考 → 强制关闭沉没，直接输出
- 任务进入执行阶段（连续工具调用）→ L2自动关闭沉没

## 4. 熔断机制（Circuit Breaker）

### 触发条件（满足任一即触发）
- 工具调用超时（60s无响应）
- 同级预算耗尽（L1:15s / L2:60s / L3:900s）
- 连续3次工具调用返回错误
- 输出token超过预算的50%仍未进入执行

### 熔断动作
1. **立即停止**当前推理链
2. **输出摘要**：已完成什么、卡在哪里、最可能的下一步
3. **降级执行**：将任务降为L1，仅做最小可交付动作
4. **请求决策**：明确告知用户需要什么信息/决策才能继续

### 熔断输出模板
```
⚡ 熔断触发 @ [层级] · 耗时 [X]s · [Y]次调用

已完成：
- [具体成果1]
- [具体成果2]

卡在：[阻塞点]

需要：[具体信息/决策]

降级方案：[最小可交付动作]
```

## 5. 恢复策略

熔断后不直接放弃，按优先级尝试：

1. **缓存复用**：之前的结果是否已足够回答？
2. **降维**：简化问题（去掉边缘情况、限制范围）
3. **拆分**：将L3拆成2个L2 + 1个L1串行交付
4. **移交**：建议用户用更专用的工具/skill处理

## 6. 自监控指标

每次会话结束，评估：
- 熔断触发次数及原因
- 分级准确率（实际耗时 vs 预算）
- 沉没开关的有效性（是否在不必要时开启了思考模式）

---

**核心原则**：智慧不等于无限沉思。奥丁献出双眼换智慧，但智慧之泉本身也有边界。知道何时停止，比知道如何继续更深刻。
