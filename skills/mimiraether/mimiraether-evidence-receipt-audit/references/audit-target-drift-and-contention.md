# 补查三类「九查清单」之外的新死法（2026-10-12 L2 审计实证）

> 来源：L2 重排上线独立复测（对象 `~/.hermes/scripts/semantic_server.py` + `wiki_semantic_mcp.py`）。
> 三个坑都不是「对方撒谎」，而是**审计装置自身**的坑——审完才发现读数不可用。

## 坑 1 · 靶在动（audit target drift）

**症状**：开工时取基线 `HEAD=695b3da`；收工时 `HEAD=57eddb6`（期间落了 5 个 commit）⇒ 先前所有「命中/未命中」判定的可比性归零。

**守则**：
1. **开工即绑 SHA + sha256**（`git rev-parse --short HEAD` + `sha256sum <file>`），并把它们写进回执。
2. **收工前复核 SHA**：若已变 ⇒ 回执里显式写「快照 SHA=X · 现值 SHA=Y · 期间 N commit 落地」，并声明结论绑 X。
3. **快照到自己的目录再测**（`cp` → `~/tmp/`）：一是防中途被改，二是写 read-only 免责（未动被审件）。
4. 反例姿势：只写「当前文件」不写 SHA —— 复核方复跑时命中的是另一个版本，读数对不上就会被判「作者环境坏了」。

## 坑 2 · 并发写者 / 并发算力（双写 + 混杂因子）

**症状 A（双写）**：你在同一张卡上追加段落时，另一路 agent 也在写同一张卡（卡内突然出现别人的「第 2 段/第 3 段」）。
**症状 B（算力污染）**：性能类读数（延迟/吞吐）被测期间**别的进程正跑同一个重模型**（实证：另一审计进程持有 3.7GB RSS 重排模型 + swap 4.0G/4.0G 已满）⇒ 同一参数两次测量 28.7s → 47.6s，差 1.7×。

**守则**：
1. **写前重取目标指纹**（`stat -c '%y %s'`）并与上次比对；变了 ⇒ 先看是不是别人的段，再决定追加位置。
2. **性能读数必记混杂因子**：`uptime`（load average）+ `free -m`（尤其 swap）+ `ps` 里是否同类重进程。三个都不记 ⇒ 该读数**不可外推**。
3. **区分「方向性结论」与「绝对读数」**：方向（重排段 ≫ 超时线）可下；绝对值只在空机成立 ⇒ 回执写明「绝对值须空机复跑」。
4. 发现并发写者 ⇒ 回执写明「勿重复计两份同题段」。

## 坑 3 · 判据自触发（self-triggering gate）

**症状**：硬门要求 `grep -c <错拼token> <我的段> ⇒ 0`；而你的「路径自检」行里**逐字写了那个 token**（为了说明判据）⇒ 自己把自己判红。

**守则**：判据行里的被计数字符串用**字符类转义**写法——把 `raymei` 写成 `ray[m]ei`：
- `grep -cE 'ray[m]ei'` 仍然命中真正的错拼；而字面量 `raymei` 在文件里**不存在** ⇒ 判据不计数自身。
- 同行注明「本行故意用 `[m]` 转义，避免判据字符串自身被计数」——否则复核方会以为你在糊弄。
- 同源：`AGENTS.md §8.5 自限`——规则不得用自身检验自身（`delta≡0`）。

## 坑 4 · 未经归因的性能声明不能只做「复跑」

**症状**：对方给「25.9s → 6.2s」；直接复跑得到 29–39s ⇒ 只能判「未复现」，说不出**为什么**，也无法给整改建议。

**守则（三段归因法，成本 ≈ 2 分钟）**：
1. **分段计时**：嵌入 / 向量 KNN / FTS5 / 重排段 各自 `time.time()`（实证：检索合计 1.5s、重排独占 29s ⇒ 一眼定位）。
2. **绕过超时直接调底层**：不要只调 `semantic_search`（会被 `RERANKER_TIMEOUT_S` 截成恒定的 30.0s，看起来像「刚好卡线」）；直接 `model.predict(pairs)` 才看得到真实成本。
3. **单变量对照**：`pool=1/3/8` × `chars=200/800` 做小矩阵（实证：`pool=1 → 8.8s`、`pool=3 → 120.5s` ⇒ 成本非线性，「调小参数」未必过线）。
