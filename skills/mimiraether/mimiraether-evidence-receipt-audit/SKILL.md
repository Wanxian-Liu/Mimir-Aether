# 证据型回执 · 九查

## 何时用
- 架构会/审计轮的**交叉审视**（审他方回执）· 复核他方读数 · 「他方声明已实测」类完工件
- 不适用：本侧自写回执（自检 delta≡0，走 §8.3 L2 他源复核）

## 九查（每条 = 一行命令 + 判据；前四条已两犯）

> **补·12（2026-10-12 实证 · 性能读数必带测量态）**：被审件里的 `Xs`/`Ys` 延迟断言，先问「**谁在跑 · 什么负载下**」；**同机并发重负载时的读数不作复现判据**。
> 实证（同一轮两单）：① L2 声明 `25.9s→6.2s`，本机争抢态实测 **31.7–38.8s**（3/3 撞 `RERANKER_TIMEOUT_S=30` · `degraded=true`）；② L3-M1 声明 `18.3/6.7/6.1s`，实测 **221.7/34.2/38.2s**（差 5–36×）。争抢态特征：14G 内存被 4 个 ~4GB 进程占满 · swap 用满 · bash 报 `fork: 资源暂时不可用`。
> ⇒ 判法：**不复现 ≠ 假**。归因写清（争抢态）、结论落「**清洁态（空闲机 · 单进程）重跑后才可定稿**」，**不得**据此判回滚。
> 附·**锁版铁证**：锁到 commit 后，除 `git show <sha>:<f>` 外，**比 md5**（提取件 vs 工作区件）——相等才可让「按工作区路径跑的命令」算锁定版读数（本轮实证：两文件 md5 两对相等 ⇒ 交付方脚本等价于锁定版）。
> **补·13（2026-10-12 二实证 · 读数↔生成器同源性）**：复核他方**读数文件**前，先核「**产出它的生成器还在盘上吗 · schema 对得上吗**」——实证：`~/.hermes/data/golive-smoke.json` 是**嵌套** schema（`http_18993{}`/`mcp{}`/`gated{}`），盘上两个候选生成器写的却是**扁平** schema（`http_rerank_field`/`mcp_schema_has_collections`/`filter_leak_count`）⇒ **生成器缺失/被覆盖 ⇒ 该读数不可复现**（与数字真假无关）。旁证法：拿读数字段集与生成器 `json.dump` 键集**逐字对**——缺键（如读数 `rerank_meta` 缺 `model`/`chars`，而锁版代码成功路径必返）即判「非同源」。同族还有**采集时点**：读数若取自**未提交工作区**，则无 commit 锚点（本轮 ` M semantic_http.py` + 2 个 untracked 冒烟脚本）。
> **附·PASS 判据完整性（假绿第三族）**：验收判据若以「**字段存在**」为过闸条件（`case $resp in *'"rerank"'*)`），注意**降级/超时路径照样返回该字段** ⇒ 「白开」与「生效」不可区分（实证：活体端到端 30.10s 贴 `RERANKER_TIMEOUT_S=30`，`degraded=false` 与 `true` 在字段层同形）。还要查**漏项**：同一动作的两版脚本判据不等价（`golive-smoke.sh:50` 漏过滤正控 `sc2`；`smoke-only.sh:33` 含 `[ "$n_out" -eq 0 ]`）⇒ 逐条把「脚本实写的判据集」与「它声明的验收项集」对齐。
0. **验标签 vs 验真身（正控假绿族 · 2026-10-12 实证）**：被审件的判据若断言的是**被测系统自己派生的字段**（`collection` / `status` / `degraded` / `ok`），先问两件事——① 该字段由**被测代码**产出吗？② 该代码有**兜底/default 分支**吗？二者皆「是」⇒ 断言可能**恒真**（判据与结论同源，delta≡0）。
   实证：`m1_eval.py:20 all(x["collection"]=="wiki")` 对 113 个真身在 `~/wiki` 之外、路径为 `../Worldweaver/…` 的件**恒真**（`collection_of()` 兜底 `return "wiki"`）⇒ 正控「零库外」假绿，端到端真漏出。
   修法口径：判据改验**真身**（`os.path.realpath(os.path.join(ROOT,file)).startswith(ROOT+os.sep)`），不验派生标签。
   一句话：**用被测系统的世界观去验被测系统 = 自证**。
1. **行首锚**：`grep -cE '^冒烟档位: [①②③④]' <件>` —— 写成 `### 冒烟档位:` 或 `**冒烟档位:**` ⇒ **0 命中**（我方一轮 + 妹妹二轮已各犯一次）
2. **契约字段（未锚定）**：`grep -c '重跑命令:'` / `grep -c '复算数字:'` —— 字段前带 `### ` 也能命中；**别用行首锚**去判这两条（会误判）
3. **引证行号核**：对每条 `L<n>` 断言跑 `grep -n <关键字> <文件>` 核真值；偏 ≥1 ⇒ 记「引证错位」
4. **文本真源定位**：引用只写文件名（如 `AGENTS.md`）⇒ 先 `grep -rl` 定位真路径（同仓常有多份同文本，四方会拼出互斥行号）
5. **回退路径存在性**：`git -C <dir> rev-parse --show-toplevel` rc=128 ⇒ 该目录**无 git** ⇒「git revert」= 幻报；再查 `*.bak*`
6. **判据 CLI 可执行性**：抽命令里的 CLI ⇒ `command -v <cli>`；rc≠0 ⇒ 该条「实测」**不可能**由该命令产生
7. **时间窗**：计数类判据必须带窗口（无窗计数 ⇒ 恒真或假阳性；`+1` 若无窗口 = 非判据）
8. **读整行**：别只读数字段 —— 实测 `EXIT code=9 elapsed=0s（脚本主动退出·非崩溃非硬杀）`，括注**否掉**了「SIGKILL」结论
9. **被审件漂移**：`stat -c %y <被引文件>` vs 回执落款；若会期内被改且无版本控制 ⇒ 要求定稿前 `sha256sum` 三件并写进决议
10. **前提实测（转述的系统行为一律要本机实证）**：被审件声称的语言/库行为（"无上限 join"、"3.12 才支持"、"会一直等"）⇒ 用**本机解释器 + 标准库源码行**实测（`importlib.util.find_spec` + 读 `asyncio/runners.py`/`base_events.py` 行号），别接受转述。本案实证：3.12.13 `Runner.close()` 传 `constants.THREAD_JOIN_TIMEOUT = 300` ⇒ **有界**，推翻「无上限 join」。（同类：读源码确认 `shutdown_default_executor` **无幂等短路** ⇒「协程内先关一次」挡不住 close 的二次 join = 反证某"更小改法"）
11. **同向修复重叠（最小改动视角的第一问）**：被审件要"修 X"时，先查**同一条路径上近期是否已有修复**——`git log --since=<N> -- <文件>` + 运行期指标复测（`journalctl … | grep -cE 'Killing process|Failed with result'` + Stopping→Stopped 耗时）。若已覆盖，最小改动答案常是「**不实施**」；少了这一查，会给出"再改一处"的方案（双修同一病 + 白增生产入口风险面）。

12. **配置类结论先查「读数来自哪个 profile」**：凡「键未生效 / 白名单不生效 / 配置改了没用」类结论，先确认**活动 profile**（`env | grep HERMES_HOME`）与**读文件路径**是否同一份——同一命令在不同 profile 下读数可**相反**（2026-10-08 实证：同一检测器、同一命令，`HERMES_HOME=~/.hermes` 侧 MATCH、`=~/.mimiraether` 侧全 NO-MATCH）。另两查：**进程内缓存**（源码注释搜 `re-reads` / `hot path`：改盘≠生效，可能要重启）与**键名族**（检测器实际产出的键 vs 名单里的键，两集合求交——别名表 `_approval_key_aliases` 不一定桥接，如 `shell execution via heredoc` ↔ `script execution via heredoc`）。

13. **恒假 / 恒真探针（两向）**：被审件给的「机器复算命令」**必须本机真跑一遍**，再问一句「这条命令**有可能变**吗」——
    - **恒假**（键名不存在）：本例 `grep -c '"positive_ctrl": true'` 实测 **0**（真形 `controls.positive.ok`）⇒ 度量的是**装置病**，会稳定报 0% 并被误诊为行为故障（同族：`grep -c 'reason:'` / `'"negative_ctrl"'`）。
    - **恒真**（字段每行都有）：本例修对键名后 `"reason":` = **894/894 = 100%** ⇒ 永远绿、**无鉴别力**。
    - 判法：`grep -c '<字面键>'` = 0 而 `grep -c '<父键>'` > 0 ⇒ 恒假；= 分母 ⇒ 恒真。**两种都不合格**。
14. **结论顶替读数**：`复算数字` 字段**不等于**该命令的 stdout——必须独立重跑取 rc + 原输出。本例：命令 rc=**1**、输出 **0**，被审件写成 `复算数字: 10`（把「维度确为 10」的**结论**回填成**读数**）⇒ 这正好违反被审件自己引的「量化论据优于假设」。
15. **弱探针代理不得替代内容读数**：`mtime` / 文件存在性 / 行数**不能**证明内容变化。本例：`mtime=10-07` 被用来**改判**「周篇末次 09-27 = 错」——实测该文件 `^### 2026-` 末条仍是 **09-27** ⇒ **把对的改判成错的**。判法：凡「因 mtime 更新 ⇒ 内容已变」的推理，必须补一条**内容级**读数（`grep -n '^### 2026-'`）证伪。
16. **活体目录 / 追加型 ledger 必须 pin 窗口**（含**自己**）：`~/.hermes/inbox/`、`probe_attest.jsonl` 等在本 run 内就会增长（实测 4 轮内 inbox 计数 176/247 → 178/249）⇒ 不加窗口的计数**复核方永远复不出同一个数**。定式：`find <dir> -maxdepth 1 -name '*.md' -newermt '<起>' ! -newermt '<止>'`（或等价的固定快照口径）。**我方在同一轮审计里当场踩坑 ⇒ 该条对审方与受审方同样适用**（§8.5：无窗计数 = 恒真或假阳性）。

17. **两把尺对账必先做受控差分，再谈结论**：拿"独立第二把尺"互审时，**不要**一比数字差就归因成"口径差"或"实现错"。定式：**把两尺的实现维度逐个列名，一次只拨一个，每拨一次读一次**（索引面 / 目标归一化 / 计数粒度 / 扫描正则 / 主键去重 / 空值处理）。本例（2026-10-11 链接策略 P0 审计）实测：两尺差 0.52pp，逐维差分后归因——索引面 −3 条、归一化 −2 条、**去重粒度 +14 条**、**扫描正则静默丢链 95 条（其中 14 条真死链）**；只看总数会得出"口径差"的错结论，逐维差分才挖出**真实现错**。
    - **子查 a · 复刻失败即证据**：若自己复刻对方实现却算不出对方读数（本例 E=699/72 vs 真值 654/15），**先把复刻对齐**——复刻不出=你的对照表不可信，禁止拿它当结论。
    - **子查 b · 正则的"静默不匹配"是最高危形态**：`[[([^]|#]+)]]` 这种「字符类排除 + 紧邻闭合符」写法会让 `[[A|B]]` / `[[A#s]]` **整条不匹配**（不是匹配出空值），全族静默丢失且不报错。判法：用宽松正则数一遍总出现次数，与对方 `out_*` 字段比，差额就是盲区。
    - **子查 c · 分母定义先冻结再设闸**：两尺若页集/去重口径不同，"|A−B|/B ≤ 10%" 这类闸门**恒 FAIL**，是判据错不是被测件错。
    - **子查 d · 复刻不可闭合时给两端锚点**：至少证明「S0 精确复现对方实现」且「对方官方读数精确可复现」，再把未闭残差（本例 21 条出链 = 2.1%）**显式标为未闭合**（§8.6 部分完成），不要沉默也不要硬凑。

## 坑（实测）
- **期望值 ≠ 读数**：`期望 …count +1` = 未过闸（§8.5：形容词/期望 = 未过闸）
- **负控不成立 = 判据不合格**：两个**串行** `flock -n <f> <cmd>` 必然都成功 ⇒ 无「败」侧；要出败必须持锁侧真实持有
- **有行 ≠ 被硬杀**：SIGKILL 语义上留不下任何行；「有行」本身否掉「硬杀」
- **锁残留**：脚本里 `grep -c '[Ll]ock'` = 0 ⇒ 无自建锁；POSIX 锁由**内核**在进程销毁时释放（含 SIGKILL）
- **OOM 与本案**：先比**时间窗**（`journalctl -k` 时间戳 vs 崩溃窗）——「路径已开火」≠「本案死因」，别把机制事实升级成因果结论
- **角色帽**：审票前换帽（不得重复一轮帽）并**全量读卡**，回执带 `角色:`/`卡路径:`/`引用规则N:` ≥3
