## 0. 架构总览

```
                         ┌──────────────────────────────────┐
                         │        HWM 分层规划层            │
                         │  战略层(阶段分解) + 战术层(Pipeline) │
                         │  共享任务表示 + 子目标潜状态传递   │
                         └──────────────┬───────────────────┘
                                        │ 子目标
                         ┌──────────────▼───────────────────┐
    任务输入 ──────────▶ │        LeWM 稳定性层            │
                         │  退化检测(SIGReg类比)            │
                         │  Surprise门控(VoE类比)           │
                         │  单超参数哲学                     │
                         └──────────────┬───────────────────┘
                                        │ 质量信号
                         ┌──────────────▼───────────────────┐
                         │     V-JEPA 2.1 深度记忆层        │
                         │  Session / Cross-session / Wiki   │
                         │  三层各加密集自检 + 层级监督      │
                         └──────────────────────────────────┘
```

**三层数据流**: 规划层产出子目标 → 稳定性层监控执行质量 → 记忆层沉淀/自检

## 1. HWM 规划层 — 分层任务执行

### 1.1 当前状态

MimirAether 现有 Pipeline: `brainstorming → plan → execute → [evaluate ⇄ optimize] → verify → ship`

**问题**: Pipeline 是**扁平**的——所有步骤在同一抽象层级，长视界任务（跨多文件重构、多阶段部署）缺乏分层推理。

### 1.2 注入设计

```
战略层 (Strategic Planner)
  ├── 输入: 用户任务 + 全局约束
  ├── 产出: 阶段级子目标序列 [G₁, G₂, ..., Gₙ]
  │   每个子目标 = {goal_desc, accept_criteria, max_steps}
  ├── 世界模型类比: 高层世界模型 P^(2)，长视界粗粒度预测
  └── 接口: 共享任务表示向量(状态+约束)传递给战术层

战术层 (Tactical Executor)
  ├── 输入: 当前子目标 Gᵢ + 当前上下文状态
  ├── 产出: 工具调用序列 [tool₁, tool₂, ..., toolₖ]
  ├── 世界模型类比: 低层世界模型 P^(1)，短视界精细执行
  └── 重新规划触发: 每 K 步后或 verify 失败时
```

### 1.3 共享表示空间

```json
// 战略层和战术层之间的通用任务表示
{
  "task_vector": {
    "intent": "重构认证模块",
    "constraints": ["不破坏现有API", "保持测试通过"],
    "current_phase": 2,
    "subgoal_stack": ["抽取接口", "实现新认证", "迁移调用方", "清理旧代码"],
    "completed_subgoals": ["抽取接口"]
  }
}
```

### 1.4 实现路径

| 优先级 | 产出 | 形式 |
|--------|------|------|
| P0 | 战略层 skill: `mimiraether-strategic-planner` | 新 skill |
| P1 | 战术层改造: 现有 Pipeline 执行加子目标约束 | 修改现有 skill |
| P2 | 共享表示定义 | `data/task_schema.json` |
| P3 | 长视界验证实验 | 3个测试用例 |

## 2. LeWM 稳定性层 — 防坍塌与意外检测

### 2.1 当前状态

MimirAether 有 `evaluator-optimizer` 循环——但评估是被动的（等待 verify 步骤才检查）。缺少**运行中**的退化信号。

### 2.2 注入设计

```
退化检测器 (Degeneration Guard)               ← SIGReg 类比
  ├── 信息密度约束: 连续 N 轮对话无新信息/新工具/新文件操作
  │   → 触发"上下文可能退化"告警
  ├── 循环检测: 重复相同工具调用 > 3 次无进展
  │   → 触发"可能陷入循环"告警
  └── 表示质量: 上下文压缩后信息保留率 < 阈值
      → 触发"上下文质量下降"告警

Surprise 门控 (Surprise Gate)                 ← VoE 类比
  ├── 位置: evaluator-optimizer 循环入口
  ├── 检测: 执行结果与预期偏差 > 阈值
  │   → 触发重规划（比正常 evaluate 更激进）
  └── 模式: 区分"表面意外"(输出格式变化) vs "物理意外"(语义矛盾)
      → 只有物理意外才触发重规划（类比 LeWM 颜色变化 vs 瞬移）

超参数审计 (Hyperparameter Audit)
  ├── 扫描 config/ 和技能参数
  ├── 标记：可合并、可消除、可自动调优的参数
  └── 目标: 从 N→k (k << N)，学习 LeWM 6→1 哲学
```

### 2.3 实现路径

| 优先级 | 产出 | 形式 |
|--------|------|------|
| P0 | 退化检测器原型 | `data/degeneration_guard.json` + 会话内检查逻辑 |
| P1 | Surprise 门控集成 | 修改 evaluator-optimizer skill |
| P2 | 超参数审计报告 | `docs/PARAMETER_AUDIT.md` |
| P3 | 稳定性设计模式文档 | `docs/STABILITY_PATTERNS.md` |

## 3. V-JEPA 2.1 深度记忆层 — 三层自检

### 3.1 当前状态

MimirAether 有 Session记忆 / Cross-session记忆 / Wiki 三层——但**缺少层级间的质量监督**。类比 V-JEPA 2.1 发现：只监督最终层输出会导致中间层信息退化（上下文 token 变成 register tokens）。

### 3.2 注入设计

```
层级监督协议 (Deep Self-Supervision for Memory)

Layer 1: Session 记忆
  ├── 自检: 当前对话的压缩表示能否线性恢复关键实体？
  ├── 类比: V-JEPA 2.1 中间层监督
  └── 指标: 实体恢复率、关键信息保留率

Layer 2: Cross-Session 记忆
  ├── 自检: persistent.json 的 key_decisions 是否仍可回溯到源会话？
  ├── 类比: V-JEPA 2.1 多层级预测
  └── 指标: 决策可追溯性、记忆新鲜度

Layer 3: Wiki
  ├── 自检: 页面之间的引用完整性、概念覆盖度
  ├── 类比: V-JEPA 2.1 多模态一致性
  └── 指标: 孤立页面率、引用断裂率

密集信息损失 (Dense Information Loss)
  ├── 不仅检查"最终压缩结果"，中间表示(摘要、标签、嵌入)也要参与质量评分
  ├── 类比: V-JEPA 2.1 dense predictive loss — all tokens 参与训练
  └── 权重: 靠近关键信息的记忆节点权重更高（类比距离加权 λ_i）

跨模态记忆统一 (Multi-Modal Memory Tokenizer)
  ├── 飞书消息 / 终端输出 / 文件内容 → 统一信息提取策略
  ├── 类比: V-JEPA 2.1 的 2D/3D 分别处理 + 模态 embedding
  └── 形式: 文档约定 + 提取模板
```

### 3.3 实现路径

| 优先级 | 产出 | 形式 |
|--------|------|------|
| P0 | 三层自检协议文档 | `docs/MEMORY_SELF_CHECK.md` |
| P1 | 记忆质量仪表板（概念） | 设计文档 |
| P2 | 跨模态记忆统一规范 | 设计文档 |
| P3 | 缩放监控：会话数增长→质量退化检测 | 集成到 `skills_qa.py` |

## 4. 三层交互协议

```
┌─────────────────────────────────────────────────────────┐
│                   HWM 规划层                            │
│  产出: 子目标序列 [G₁, G₂, ..., Gₙ]                    │
│  向下传递: 当前子目标 Gᵢ + 约束向量                     │
└──────────────────────┬──────────────────────────────────┘
                       │ Gᵢ
                       ▼
┌─────────────────────────────────────────────────────────┐
│                   LeWM 稳定性层                         │
│  监控: 退化信号、Surprise 偏离                          │
│  向上反馈: "退化警告"→战略层可能需重新分解              │
│  向下传递: "当前执行质量 OK" / "需重规划"               │
└──────────────────────┬──────────────────────────────────┘
                       │ 质量报告
                       ▼
┌─────────────────────────────────────────────────────────┐
│                V-JEPA 2.1 深度记忆层                    │
│  沉淀: 执行结果 + 质量元数据 → 三层记忆                 │
│  向上反馈: "记忆质量趋势"→影响未来规划偏好             │
│  自检: 每层独立质量评分 → 退化预警                      │
└─────────────────────────────────────────────────────────┘
```

**关键原则**:
- **向下传递是具体的**（子目标、质量信号）
- **向上反馈是趋势性的**（退化警告、质量趋势）
- **每层有自己的"预测器"**：规划层预测任务进展、稳定性层预测质量风险、记忆层预测信息衰减

## 5. 最小可行原型路线

按改动代价从小到大排列：

### MVP-1: LeWM 退化检测（最快，~50行）
- 新增 `data/degeneration_guard.json` 记录退化规则
- 在 evaluator-optimizer 循环中插入退化检查
- **收益**: 立即防止对话循环/空转

### MVP-2: HWM 分层规划（中等，新 skill）
- 创建 `mimiraether-strategic-planner` skill
- 定义子目标格式
- 现有 Pipeline 增加阶段感知
- **收益**: 长任务成功率提升

### MVP-3: V-JEPA 记忆自检（基础设施）
- `docs/MEMORY_SELF_CHECK.md` 文档化
- 三层各加自检规则
- **收益**: 记忆质量可量化
