# MimirAether 架构评分方法论

**日期**：2026-05-21  
**来源**：EV-A04（琬弦架构方案 §1.2）

## 评分体系

| 子维度 | 权重 | 当前自评 | 目标 | 评分标准 |
|--------|:--:|:--:|:--:|------|
| **职责清晰度** | 25% | 5.5 | 8.0 | 1=monolith, 10=每个模块单一职责、接口明确 |
| **耦合度** | 20% | 5.0 | 7.5 | 1=全局 import 循环, 10=依赖方向统一、无循环 |
| **可测试性** | 15% | 4.0 | 7.0 | 1=0 测试, 10=核心路径全覆盖+依赖可 mock |
| **可替换性** | 15% | 6.0 | 8.0 | 1=硬编码, 10=抽象层可换实现（如换 DB/换 LLM） |
| **启动/运行时性能** | 10% | 7.0 | 8.0 | 1=启动 >60s, 10=启动 <5s + 无阻塞 import |
| **配置化程度** | 10% | 6.0 | 7.5 | 1=全部硬编码, 10=config.yaml + env 完全外置 |
| **文档完整度** | 5% | 8.0 | 9.0 | 1=无 docs, 10=架构图+ADR+path-contract 齐备 |

## 当前自评细则

| 子维度 | 自评 | 依据 |
|--------|:--:|------|
| 职责清晰度 | 5.5 | `core_loop.py` 与 `agent_loop.py` 职责重叠（都做了消息调度）；`prompt_builder.py` 含安全逻辑 |
| 耦合度 | 5.0 | `gateway/` 与 `agent/` 双向 import；`router_mixin` 3568 行；mixin 拆分引入 7 NameError |
| 可测试性 | 4.0 | tier0 181+2 PASS 但覆盖率 ~5%；无集成测试（agent_loop 全链路） |
| 可替换性 | 6.0 | `tools/` 注册机制较好；LLM provider 可换（DeepSeek ↔ OpenRouter） |
| 启动性能 | 7.0 | Gateway 启动 ~10s；Mimicore 延迟 import 不阻塞 |
| 配置化 | 6.0 | `config.yaml` + `.env` 有，但 `CLI_CONFIG` ImportError 暴露硬编码问题 |
| 文档完整度 | 8.0 | ADR + Playbook + path-contract + OPERATIONS + SECURITY + 审计日志 齐备 |

## 加权总分

| 计算 | 结果 |
|------|:--:|
| 5.5×0.25 + 5.0×0.20 + 4.0×0.15 + 6.0×0.15 + 7.0×0.10 + 6.0×0.10 + 8.0×0.05 | **5.48** → 四舍五入 **5.5/10** |

> 琬弦方案自评 7.8 — 存在 **2.3 分差距**。可能原因：方案评分标准偏乐观（假设所有设计已落地）；本评分基于**代码现状**而非设计文档。
