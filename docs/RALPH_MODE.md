# Ralph 模式（严格迭代）

在主线开发中启用本模式时，代理/协作者按本节执行，**不以「感觉好了」收尾**，以**可重复验证**收尾。

## 何时启用

用户或团队明确说 **「启用 Ralph 模式」** / **「按 Ralph 模式」**，或任务标注 `ralph-mode`。与 **`docs/DEVELOPMENT_NORTH_STAR.md`**、**`./run_ralph_tier0.sh`** 同一主线：先行为可证，再谈扩展。

## 规则（与实现对齐）

| # | 规则 | 本仓库落地 |
|---|------|------------|
| 1 | 在沙盒中自动执行该「技能」 | **技能** = 当前正在交付的工件（模块、脚本、`SKILL.md` 逻辑、或一次 PR 的变更集）。在终端执行约定验证；需要完整环境时用 `required_permissions: all`（与 Cursor 沙盒策略一致）。 |
| 2 | 捕获执行错误、逻辑漏洞、输出不完整、边界异常 | 保存 pytest/脚本的 **stderr、失败用例名、断言**；对文档类检查断链、前后矛盾、缺步骤。 |
| 3 | 自动定位原因，给出修复并改逻辑 | 先最小复现 → 改代码/技能 → 不扩大范围（对齐 `CLAUDE.md`）。 |
| 4 | 沙盒内重新验证直到稳定 | 代码路径：**`./run_ralph_tier0.sh`**（Gate1–Gate3）；必要时加针对性 `pytest` 文件。 |
| 5 | 每轮输出四段 | **轮次 → 问题 → 修复 → 验证结果**（见下模板）。 |
| 6 | 完成判据 | **连续 3 轮**验证**零失败**（同一套命令、同一工作树）。若中途任一失败，计数清零，修复后从第 1 轮重新计。 |

## 验证命令（默认）

```bash
cd ~/.openclaw/projects/MimirAether   # 或本仓库根
./run_ralph_tier0.sh
```

与 pre-push / CI 一致。仅改文档且无代码路径时，可改用「约定检查」（如链接存在、`markdown` 人工清单），但须在当轮 **验证结果** 中写清**未跑全量 Ralph 的原因**。

## 迭代日志模板（每轮粘贴）

```
### Ralph 模式 — 第 N 轮
- **问题**：（失败用例 / 现象 / 不完整点）
- **修复**：（文件/逻辑要点，1～5 条）
- **验证结果**：`./run_ralph_tier0.sh` → PASS / FAIL（附摘要行）
```

## 完成判据（本模式）

- [ ] 连续 **3** 次 `./run_ralph_tier0.sh` 退出码 0，且输出无 Gate 失败。
- [ ] 若本轮改了 Python，三轮必须用同一提交或连续未改代码状态（避免「第一轮绿、暗改又未测」）。
