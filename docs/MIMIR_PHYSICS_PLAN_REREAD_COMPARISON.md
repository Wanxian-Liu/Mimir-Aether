## 3. 原方案缺失的：重读发现 5 个可以深化的点

### 3.1 🔴 缺失：代价函数框架

**JEPA 原文**：
```
C(s) = IC(s) + TC(s)
IC(s) = Σᵢ uᵢ · ICᵢ(s)    (内在代价，不可变)
TC(s) = Σᵢ vᵢ · TCᵢ(s)    (可训练评判者)
```

**原方案现状**：PHY03 有"约束推理"和"可行性判断"，但没有显式建模为"代价函数最小化"。

**改进**：在 PHY03 中显式引入代价函数概念：

```
IC(s) = 
  +∞  如果违反物理定律（能量不守恒、力超限）
  +∞  如果违反安全约束（绳子断裂、电流超载）
  0   如果状态完全合法

规划 = 在动作空间中搜索，找到最小化 IC 的路径
```

**影响**：PHY03 的设计从"约束检查"升级为"代价最小化规划"，更契合杨立昆的推理框架。

---

### 3.2 🔴 缺失：System 1 vs System 2 显式设计

**JEPA 原文**：
- System 1（快速直觉）：Reactive behavior via policy module
- System 2（慢速推理）：Reasoning = planning = inference-time cost optimization

**原方案现状**：只设计了 System 2 路径（公式推导 + 数值求解），没有考虑"简单问题走快速路径"。

**改进**：增加一个快速路径：

```
输入问题
  ↓
快速分类器（System 1）
  ├── "简单查表"：直接返回已知公式和常量
  │   例："重力加速度是多少？" → 9.8 m/s²（不走求解器）
  └── "需要推理"：走完整求解链路（System 2）
      例："5kg的球从10m高处落下，落地速度？"
```

**影响**：不是所有问题都需要跑 SymPy 推导。加 ~30 行查表逻辑，显著降低延迟。

---

### 3.3 🟡 缺失：Energy-Based Model 的显式对齐

**JEPA 原文**：F(x,y) = 能量函数 — 兼容则低能，不兼容则高能。不给硬答案，给"兼容性评分"。

**原方案现状**：公式匹配器给唯一的 Top-1 匹配，而不是 Top-N 候选带兼容性评分。

**改进**：公式匹配改为输出 Top-3 候选 + 兼容性评分：

```python
FormulaMatcher.query("灯泡不亮了"):
    1. 欧姆定律 V=IR        compat=0.92  ← 最高兼容性
    2. 焦耳定律 Q=I²Rt      compat=0.67
    3. RC电路充放电          compat=0.34
```

不确定时（最高兼容性 < 0.7）→ 反问用户确认，而不是硬猜。

**影响**：这是 JEPA 的"不确定时不硬猜"原则在物理推理中的直接应用。~30 行改动。

---

### 3.4 🟡 缺失：Configurator 概念

**JEPA 原文**：Configurator 是"执行控制"——动态配置所有模块的参数以适应当前任务。

**原方案现状**：PhysicsRouter 做领域选择，但这是硬编码的路由。没有 Configurator 的"动态配置"概念。

**改进**：PhysicsRouter 加一个显式的 `PhysicsConfigurator` 层：

```python
PhysicsConfigurator:
    输入 → 判定领域 → 配置求解器参数
    ├── mechanics: 激活 NewtonSolver, 精度=1e-6, 维度=3
    ├── electrical: 激活 CircuitSolver, 精度=1e-9, 维度=N
    └── thermal: 激活 HeatSolver, 精度=1e-6, 维度=1
```

**影响**：这是架构层面的微调，不是功能差异。让 PHY02（多领域扩展）的领域路由器有更清晰的 JEPA 对齐。

---

### 3.5 🟡 缺失："不训练，只计算"的显式声明

**原方案**：§2 底部有一行"不训练神经网络"，但没说为什么不训练、为什么不需要训练。

**重读发现**：JEPA 的关键洞察是"SSL 预训练完就冻结，在上面接任务头"。应用到物理模型：**我们不需要预训练，因为我们直接用人类已经推导好的公式（人类几百年的物理知识 = 天然预训练权重）**。

**改进**：在方案 §1 加一段：

> **为什么不训练神经网络？**
> 杨立昆的 JEPA 用 SSL 学抽象表征，是因为视觉/视频数据没有显式的公式。物理有——牛顿、欧姆、麦克斯韦已经推导了精准的数学公式。用这些公式 = 用"人类级的预训练权重"。训练一个神经网络去逼近 v=sqrt(2gh) 是浪费。直接用公式求解 = 零近似误差。

**影响**：这是对刘哥"CPU only"约束的最深层理论支撑——CPU 不仅能做，而且比 GPU 训练更正确（无近似误差）。

## 4. 原方案需要重新审视的 1 个点

### 4.1 🟡 PHY03 名称：从"约束推理+反事实"升级为"规划引擎"

**原因**：重读发现杨立昆的世界模型的核心用途不是"验证约束"，而是"**推理时代价优化**"——给定目标，用世界模型模拟各种动作序列，找最小代价路径。

**PHY03 原始设计**：可行性判断 + 反事实 + 参数扫描。

**PHY03 应扩展为**：以上 3 项 + **规划**（给定初始状态 + 目标状态，世界模型搜索最小代价路径）：

```
输入："如何用最小的力把一个箱子从地面推到 1m 高的台子上？"
世界模型模拟：
    路径 A：直接抬 → 需要力 = mg = 98N × 1m → 做功 98J
    路径 B：用斜面 30° → 需要力 = mg sin30° = 49N × 2m → 做功 98J（力小但距离长）
    路径 C：用杠杆 → ...
→ 回报最优方案（根据用户偏好：最小力 / 最小功 / 最快）
```

**影响**：PHY03 从 ~150 行扩展到 ~250 行，但实现了杨立昆世界模型的真正核心能力。这是路线 1 的灵魂。
