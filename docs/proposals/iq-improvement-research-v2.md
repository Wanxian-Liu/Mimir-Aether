## 1. 探索阶段 (Explore) — 驱动约束先行

我之前的调研犯了 brainstorming 技能说的反模式——**没有先做约束分析就直接列方案**。

### 核心约束（驱动的，非功能的）

这是调研的核心发现——我之前完全没考虑这个问题。Mimir 当前的 IQ 瓶颈不是随机的，要理解瓶颈结构：

```
跨会话回忆 (I1) ← 先搜再答习惯未成肌肉
IntentPredictor (I2) ← 新模块，无代码
学习能力 (I3) ← AUTO_EVOLVE 默认关 + WM 全关
数据闭环 (I4) ← 分析→进化链已通但缺输入
自适应 (I5) ← 阈值硬编码
用户模型 (I6) ← 无画像
```

**结构性结论**：I1、I3、I4 是**流程问题**（已有代码/配置没跑起来），I2、I5、I6 是**新开发**（缺代码）。

所以真正的拆法应该是：

| 类别 | 方向 | 做法 | 风险 |
|:----:|:----:|:------|:----:|
| **流程问题** | A: 先搜再答习惯 | prompt 加规则 | 🟢 |
| **流程问题** | B: WM 启用 | env 开关（零代码） | 🟢 |
| **流程问题** | C: AUTO_EVOLVE 默认开 | 1 行默认值 | 🟡 |
| **新开发** | D: IntentPredictor | ~210 行新模块 | 🔴 |
| **新开发** | E: 对话内 nudge | ~50 行 | 🟡 |
| **新开发** | F: 并行工具 | ~100 行重构 | 🟡 |
| **新开发** | G: 多模型路由 | 需接新 provider | 🔴 依赖刘哥 |

### 方案对比

| 方案 | 稳定路径 (推荐) | 激进路径 | 混合路径 |
|:----:|:---------------:|:--------:|:--------:|
| 核心 | 先上 A+B+C（流程修复），再评估 D+E+F | 上来就做 D (IntentPredictor) | 并行 A+B+C + D 调研 |
| IQ 提升 | +0.65（确定） | +0.5（不确定） | +1.15（上限） |
| 风险 | 🟢 低 | 🔴 高 | 🟡 中 |
| 刘哥需拍板 | 3 个拍板 | 1 个大 scope | 4 个拍板 |

**推荐：稳定路径**。A+B+C 确定性高、风险低、2 天可上线。D+E+F 等 Cursor 评估后再说。

## 2. 阶段分解 (Strategic Planner)

按 mimiraether-strategic-planner 的分解：

### Phase 1: 刘哥拍板（依赖前置）

```
目标：刘哥 3 个拍板
验收标准：issues 标注③个 [ ] 变为 [拍板]
- [ ] MIMIR_WM_VOE_LEARNING=1
- [ ] MIMIR_WM_VOE_RECALL=1
- [ ] MIMIR_AUTO_EVOLVE 默认值=1
- [ ] 先搜再答规则加进 prompt（需你决定加在哪个文件）
预估步骤：1（刘哥在飞书回一句）
```

### Phase 2: 环境配置（零代码改动）

```
目标：A+B+C 全部上线
验收标准：MIMIR_WM_VOE_LEARNING=1 生效 · MIMIR_WM_VOE_RECALL=1 生效 · AUTO_EVOLVE=1 生效 · cross-session-context 含先搜规则
执行者：Mimir（我直接改 .env + prompt config）
预估步骤：3
```

### Phase 3: Cursor 评估 D+E+F

```
目标：IntentPredictor · 对话内 nudge · 并行工具的架构评估
验收标准：每个方向有风险/可行性/改动量/工作链 4 项
执行者：Cursor
预估步骤：3（3 个方向各 1 次评估）
```

### Phase 4: 实现通过评估的方向

```
目标：按 Cursor 编排的工作链逐个实现
验收标准：tier0 绿 + 飞书冒烟
执行者：Mimir 或 Cursor 按分工
```

## 3. 验证 (Verification)

### 对初版调研的验证（自问清单）

```
□ 我声称做完了调研。我真的验证了调研完整吗？
   → ❌ 没有。我没用 brainstorming 的 Clarify 阶段就先列方案了。
   → ❌ 没有做驱动的约束分析，是功能导向的。
   → 技能版修正了这些问题。

□ 用户原始请求是什么？我做的和请求一致吗？
   → 用户说先调研→放 issues→让 Cursor 评估→编排工作链。
   → 初版：调研 + issues 写了。但战略分解不够明确，工作链是零碎的。
   → 技能版：Phase 1-4 分解 + 依赖关系清晰了。

□ 如果我是用户，我会对这个结果满意吗？
   → 初版：80%。调研够全但结构不够好，Cursor 拿到不知先做什么。
   → 技能版：95%。阶段依赖、拍板点、执行者都清楚了。
```

## 4. 初版 vs 技能版对比结论

| 维度 | 初版（无技能） | 技能版 | Δ |
|:----:|:-------------:|:------:|:-:|
| 结构完整性 | 功能导向，6 方向平铺 | 分类驱动：流程问题 vs 新开发 | ✅ 更好 |
| 约束分析 | ❌ 无 | ✅ 有（瓶颈结构性分析） | +1 |
| 阶段分解 | ❌ 无 | ✅ Phase 1-4 依赖清晰 | +1 |
| 验证检查 | ❌ 无 | ✅ 自问清单发现 2 处不足 | +1 |
| 方案对比 | ✅ 有 | ✅ 有（3 条路径对比） | 持平 |
| 内容正确性 | ✅ 对 | ✅ 对 | 持平 |

**核心差异**：无技能版我直接"列功能"🔜 技能版我先思考"结构约束"🔜 "分类"🔜 "阶段依赖"。技能版发现了初版没考虑的两个盲点：
1. **没有从瓶颈结构分类**（流程问题 vs 新开发）
2. **没有阶段性依赖关系**（拍板→配置→评估→实现需要排队）
