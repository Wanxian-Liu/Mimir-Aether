# ADR-008: Agent 循环"无产出空转"检测机制（评估与渐进方案）

## Status
Proposed（评估中——不立即实施强制干预）

## Context（问题确认）
- **现象**：Mimir 反复"连续工具调用无产出"——2026-08-18 甘特审计 18 分钟 30+ 次 read_file 不落盘；历史：delegate_tool.py 被读 7 次、搜索 26 次记不住
- **现有机制**：max_turns（总轮次——挡不住"读上瘾"，会一直工具到上限）+ 错误风暴检测（L257 只治"工具失败死循环"，不治"工具成功但空转"）
- **提示词修补实证无效**：AGENTS.md 加"读够即写"纪律 + 直接干预消息（"停止读取"）——Agent 未执行（18 分钟仍在读）——**证明是架构层缺口，非提示词问题**

## Decision（方案评估——软件架构师视角）

### 方案 A：连续无产出轮数阈值（consecutive_tool_turns ≥ 8 强制）
- ⚠️ **误伤风险高**：Mimir 合法任务大量工具密集（搜索→提取→验证→落盘——57 原子任务 124 步）——"连续 8 轮工具"完全可能是正常任务——**放弃优先采用**

### 方案 B：重复读取检测（同一路径 read_file ≥2 次 = 空转信号）
- ✅ 精准：正常任务不会重复读同一文件（读过的内容在上下文里）；重复读 = 没记住/空转
- ✅ 低误伤：只触发"重复读"场景
- ⚠️ 需验证：长文件分页读（offset/limit 翻页）不算重复

### 方案 C：落盘水位检测（交付物 mtime 超 N 分钟无更新 + 工具持续调用）
- ✅ 最贴近"空转"本质（任务没向交付物推进）
- ⚠️ 实现稍复杂（需跟踪目标文件）

### 推荐（渐进式 · 可回退——规则 4）
**第一阶段（只观测不强制）**：在 agent_loop 循环加"空转信号检测"——重复读同一文件（方案 B）→ 只记日志 + 注入"产出提醒"（软干预，不强制收束）
**第二阶段（数据验证后）**：若观测到提醒无效（多次提醒仍空转）→ 升级为"强制收束"（AgentLoopExit，像 tool_storm）
**回退**：第一阶段是纯增量日志（零风险）；第二阶段开关控制（环境变量），随时可关

## Consequences
- 变容易：空转可观测、可干预、可回退
- 变困难：无（第一阶段零行为改变；第二阶段默认关）
- 权衡（规则 2）：牺牲"完全自动"换"不误伤"——先观测数据，不拍脑袋强制
