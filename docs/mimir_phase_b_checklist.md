## 任务类型覆盖（启动期默认）

成长路线图列有四类任务：**代码 / 研究 / 执行 / 编排**。  
**启动阶段 2 的默认约定**：在将 MAINLINE 里程碑 **B** 标 **绿** 之前，至少完成：

- **代码**：一次可合并的代码类交付（PR 或等价 diff + 验证命令）。
- **执行**：一次脚本/工作流/真环境操作类交付（命令、退出码、结果摘要）。

其余两类（**研究**、**编排**）应在标 **B 绿** 前各至少 **1** 次最小样本；若暂时不做，在 §汇总表写明 **阻塞：计划 YYYY-MM-DD 前补**。

## 建议的 B「绿」门槛（MAINLINE）

在 **`docs/MAINLINE_STATUS.md`** 将里程碑 **B** 标 **绿** 前，建议同时满足：

1. 本节 **B1–B4** 在最近 **≥ 3** 个**不同**伙伴任务上均有勾选与简短证据（可附本节 §执行记录或外链）。
2. 上节 **任务类型覆盖** 四类均已各至少一次最小样本，或已书面降级并更新成长路线图/MAINLINE 说明。

（门槛为仓库内**工程化约定**；与路线图原文可并行，以团队裁决为准。）

## 如何委托 MimirAether 代理执行

将下面整段复制给 **MimirAether 代理**（已打开本仓库、可执行终端）。**密钥与人机步骤**仍可能需你本人完成。

```
请阅读 docs/mimir_phase_b_checklist.md。在 git 根 ~/.openclaw/projects/MimirAether（或当前 MimirAether 根）协助整理「里程碑 B」证据：

- B1：最近一个「从需求到交付」的完整任务：交付物是什么（PR 链接 / 文件路径 / 对话结论）、验收方式、是否达到用户可接受状态。
- B2：同一任务中是否出现「先澄清目标/成功标准」的记录（引用对话或 PR 描述中的原句）；若没有，标 [ ] 并写改进点。
- B3：同一任务中遇到障碍时：简述假设 → 尝试 → 结果（可贴脱敏日志摘要）；若全程无卡点，写「无阻塞」。
- B4：任务后复盘归档：路径或链接（见文档 §B4）；若仅人工归档，写明文件名与存放根目录；勿打印 secret。

输出格式：按 B1/B2/B3/B4 分节；每项 [x]/[ ]；附「任务类型」归类（代码/研究/执行/编排）。不要打印 API key 或完整 .env。
```
